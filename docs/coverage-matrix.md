# 知识覆盖矩阵

## 完成定义

任何章节必须同时具备以下七项，才能标记为“已完成”：

- 概念：解释是什么、为什么、何时使用及常见误区。
- 示例：包含最小示例、逐行状态和输出。
- 交互：学习者能够修改参数或代码并观察变化。
- 练习：至少包含辨析、预测、实操三类任务。
- 排错：包含典型错误、错误信息阅读和修复过程。
- 评估：有明确通过条件，并记录需要提示还是独立完成。
- 产出：知识点进入一个可运行的小项目，而不是孤立代码片段。

状态符号：`✅ 已完成`、`🟡 开发中`、`⬜ 待开发`。

## 全流程毕业项目

最终项目会贯通：

环境准备 → Linux/Shell 自动化 → Python 工程 → MySQL 数据 → NumPy/Pandas 处理 → 数学解释 → 机器学习基线 → PyTorch 深度模型 → 指标评估 → 推理服务 → 测试与故障排查。

学习者必须能够画出全流程、解释每层职责、替换关键组件、修复刻意注入的故障，并独立重建最小可运行版本。

## 架构待补能力

当前版本已把关卡内容抽象成统一数据协议，并支持每关独立进度。平台能力按照 [product-roadmap.md](product-roadmap.md) 分阶段构建，仍需逐步补齐：

- 真正隔离的 Python 代码执行沙箱，而不是只运行预设模拟。
- 间隔复习与错题重现，根据遗忘时间主动安排任务。
- 学习档案、跨设备同步、教师评语和人工考核记录。
- 项目提交验收：读取学习者代码、运行测试并给出诊断。
- 内容版本迁移，课程升级时保留已经获得的学习证据。
- 可观测性：记录卡点类型，而不是只记录最终分数。
- 权限与安全：代码执行限时、资源限制、敏感信息隔离。
