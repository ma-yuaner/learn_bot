# AI 探险家学习设计

## 项目目标

把培训讲义重构为“能运行、能操作、能评估”的项目式课程。讲义提供知识范围，本站内容使用自己的结构、示例和表达重新编写。

学会一个知识点的标准不是看过，而是学习者能够：

1. 用自己的话解释概念以及它解决的问题。
2. 不运行代码就预测关键状态和输出。
3. 修改代码完成一个有明确验收条件的任务。
4. 根据错误信息定位原因并修复。
5. 在新情境中迁移使用。

## 每个关卡的固定结构

| 阶段 | 学习者动作 | 系统证据 |
| --- | --- | --- |
| 建模 | 阅读短讲解、辨析相近概念 | 概念检查点 |
| 观察 | 逐行阅读最小代码 | 状态追踪 |
| 预测 | 运行前选择输出或状态 | 推理得分 |
| 实操 | 修改输入、代码或配置 | 自动验收 |
| 排错 | 修复刻意设计的错误 | 错误类型记录 |
| 解释 | 用自己的话说明原因 | 表达评分与追问 |
| 迁移 | 完成不同上下文的小任务 | 能力徽章 |

## 评估模型

- 知识：能否准确区分核心概念。
- 推理：能否按执行顺序预测状态。
- 实操：能否完成带约束的任务。
- 排错：能否解释错误原因并修复。
- 表达：能否用非术语堆砌的语言讲明白。
- 迁移：能否在新问题中独立选用知识。

第一版页面先展示知识、推理、实操、表达四维评分。排错和迁移会随第二批关卡加入。

## 五级考核

每个学习区域都不能只做零散题目，必须逐层验收：

1. L1 知识点：定义、辨析、预测和最小操作。
2. L2 模块：组合多个知识点完成一个功能。
3. L3 框架：讲清架构、模块边界、依赖、数据流、异常流与技术取舍，并从空目录搭出最小骨架。
4. L4 综合项目：跨区域完成需求、测试、排错和复盘。
5. L5 面试官：限时问答、连续追问、现场编码、系统设计和项目深挖。

框架考核不会只问“用了什么”。至少会问：

- 请求或数据从哪里进入，经过哪些模块，在哪里被转换和保存？
- 每个目录和模块的职责是什么，为什么不能全部写在一个文件？
- 正常流程和失败流程分别怎样传播？
- 去掉某个组件会发生什么？替换方案有什么代价？
- 如何证明程序正确、性能可接受、错误能够被观察？
- 如果从空目录重建，第一步到可运行最小版本分别做什么？

考核结果分为“未接触、需要提示、可独立完成、可解释与迁移”四档。只有达到最后一档，区域才算真正掌握。

## 覆盖完整性

课程开发使用 [coverage-matrix.md](coverage-matrix.md) 跟踪所有区域。一个章节只有同时具备概念、示例、交互、练习、排错、评估和项目产出，才允许标记为完成。

## 内容路线

现有资料被组织为 11 个区域：装备环境、Linux、Shell、Python、算法与数据结构、MySQL、NumPy/Pandas、数学基础、机器学习、PyTorch、CNN/RNN。

推荐学习顺序不是机械照着文件名走，而是：

环境 → Linux → Shell → Python → 算法 / MySQL → NumPy/Pandas → 数学 → 机器学习 → PyTorch → CNN/RNN。

每完成一个区域，都要产出一个可运行的小项目；最终项目是一个具备数据处理、模型训练、评估和服务化能力的 AI 应用。
