# 手机学习与多设备同步路线

目标是让学习者能够在电脑阅读和编写代码，在手机完成阅读、预测、测验与复习，并在任何设备继续同一份学习进度。

这不是单独增加一个“同步按钮”，而是一组需要学习和考核的完整工程能力。

## 学习模块

### 1. 响应式与移动端交互

- 使用移动优先布局处理不同屏幕宽度。
- 为触摸操作提供足够点击区域。
- 代码编辑器支持横向滚动、缩进辅助和外接键盘。
- 区分适合手机的任务与适合电脑的完整编码任务。
- 使用无障碍语义和键盘导航。

考核：解释页面从桌面双栏变为手机单栏的布局规则，并修复一个触摸区域过小的问题。

### 2. 身份与会话

- 注册、登录、退出与密码安全。
- Cookie、Session、Token 的区别。
- 短期访问令牌与安全刷新机制。
- 设备列表、会话失效和异常登录处理。
- 最小权限与服务端鉴权。

考核：画出从手机登录到服务端确认用户身份的完整请求链路。

### 3. 云端学习档案

- 用户、课程版本、关卡进度、答题记录、代码提交和人工评语的数据模型。
- 自动证据与人工考核证据分开保存。
- 数据库事务、唯一约束和幂等请求。
- 学习者的数据导出与删除。

考核：设计关系表及约束，证明重复提交不会制造两条错误进度。

### 4. 多设备同步与冲突

- 服务器版本号、更新时间和客户端最后同步版本。
- 乐观并发控制，避免后保存的旧数据覆盖新数据。
- 答题记录采用追加事件，掌握度由证据重新计算。
- 同一题在手机和电脑同时修改时进行字段级合并或提示选择。
- 网络断开后的重试、幂等键和指数退避。

考核：处理“电脑完成关卡后离线，手机又完成新测验，电脑稍后上线”的合并案例。

### 5. PWA 与离线学习

- Web App Manifest 与安装体验。
- Service Worker 静态资源缓存。
- IndexedDB 保存离线答题队列。
- 在线后按顺序提交并处理部分失败。
- 课程版本升级时的缓存迁移和回滚。

考核：解释为什么不能缓存所有 API 响应，并为课程静态内容与学习进度设计不同缓存策略。

### 6. 服务端代码执行

- 手机只提交代码文本，真正执行发生在隔离服务。
- 队列、任务状态、超时、资源配额和取消。
- 容器或微虚拟机隔离文件、网络和进程。
- 公开测试、隐藏测试和防作弊策略。
- 执行日志脱敏及结果持久化。

考核：画出“手机提交代码 → API → 队列 → 沙箱 → 测试 → 结果同步”的完整架构，并识别信任边界。

## 实施顺序

1. 当前阶段：响应式页面、本地进度、受限单机代码验收。
2. 账号阶段：后端 API、数据库、登录和云端学习档案。
3. 同步阶段：版本号、幂等请求、离线队列和冲突处理。
4. PWA 阶段：可安装、课程离线缓存和移动端优化。
5. 生产沙箱阶段：队列、隔离执行、配额、审计和监控。

每个阶段完成后都要有自动测试、故障注入和框架口试，不能只验证“正常情况下可以同步”。
